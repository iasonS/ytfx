# ytfx Reference

## Architecture

`index.js` is the Express service on port 3000. Discord crawler routes return bounded oEmbed/thumbnail-derived metadata with local `/proxy/video/:id` media URLs; the proxy lazily invokes yt-dlp, caches stream URLs for two hours, and relays upstream bytes. `db.js` stores analytics, `metrics.js` tracks operation timing, and `public/` contains static assets. `public/mhstats/` is the MH Stats fan game (ADR-012): `game.js` and `storage.js` are pure ES modules, `app.js` owns the DOM, and `deck.json` plus `img/` are generated by `tools/mhstats/` and committed. A run carries an **aim** (`h` highest, `l` lowest) that decides whether it is judged against the best or the worst line its seven monsters allow. Links: `?r=CODE` shows a finished run, `?d=CODE` is a challenge. A challenge deals the other player either the **same** seven monsters (totals compared directly) or a **random** seven (compared on each player's percentage of their own perfect line, since totals across different draws are not comparable). A challenge with no picks is an *open* one, sent from the Duel tab before anyone has played. The share code is `seed.picks[.mask][.flags]`, flags being the aim character plus an optional draw character (`h`, `l`, `hr`, `lr`); the mask is always written when flags are, because `l` is a legal base-36 mask.

## Configuration

- `PORT` (default `3000`)
- `VIDEOS_DIR` (Docker default `/data/videos`)
- `BASE_URL` (otherwise request host is used)
- `YOUTUBE_COOKIES_B64` or `YOUTUBE_COOKIES`
- `DB_PATH`
- `STATS_TOKEN`

## Validation

Run `npm test` for the full suite, or `npx vitest run tests/unit.test.js tests/mocked.test.js` for the focused metadata/proxy tests. The MH Stats tests are `tests/mhstats-*.test.js` and run under `npm test`. The browser smoke test needs a running server: `PORT=3999 node index.js &` then `node tools/mhstats/smoke.mjs`.

## MH Stats deck

Rebuild with `node tools/mhstats/build.js` (see `tools/mhstats/README.md`). Deck numbers come only from the sources, `tools/mhstats/data/refinement.json` or `tools/mhstats/data/curation.json`; never hand-edit `deck.json`. `tools/mhstats/data/curation-report.md` is the audit surface for every value that did not come straight from a game. `public/mhstats/credits.txt` carries required attribution and must ship.

## Self-hosted Docker

Build with `docker build -t ytfx .` and run with a persistent host volume mounted at `/data`. Rebuild and restart only this service when deploying image changes; configure the public `BASE_URL` and required cookies through the runtime environment.
