# ytfx Reference

## Architecture

`index.js` is the Express service on port 3000. Discord crawler routes return bounded oEmbed/thumbnail-derived metadata with local `/proxy/video/:id` media URLs; the proxy lazily invokes yt-dlp, caches stream URLs for two hours, and relays upstream bytes. `db.js` stores analytics, `metrics.js` tracks operation timing, and `public/` contains static assets. `public/mhstats/` is the MH Stats fan game (ADR-012): `game.js` and `storage.js` are pure ES modules, `app.js` owns the DOM, and `deck.json` plus `img/` are generated by `tools/mhstats/` and committed. A run carries an **aim** (`h` highest, `l` lowest) that decides whether it is judged against the best or the worst line its seven monsters allow. Every run is dealt **eight** monsters: seven to face and a reserve, which the one-per-run **reroll** swaps in for whatever is on the table. A pool therefore needs eight monsters, not seven, which is why each generation must have at least eight. `?r=CODE` shows a finished run; the share code is `seed.picks[.mask][.aim+rerollAt]`, where the fourth field is the aim character plus the position a reroll was spent on. The mask is always written when that field is, because `l` is a legal base-36 mask. Rebuild a run with `rebuildRun`, never `drawMonsters`, or a rerolled run comes back with the wrong seven. **Live duels** (ADR-015) are the one server-backed part: `mhstats-rooms.js` keeps rooms in memory behind six routes under `/mhstats/api/rooms`, and `?room=CODE` joins one. A room deals either one seven for both players or one each (`draw` `s`/`r`); with one each the totals are not comparable, so the duel is settled on each player's percentage of their own perfect line. **Duel again** re-deals in the same room once both ask. The server withholds a player's picks from their opponent until both have finished, which is the only reason it exists.

## Configuration

- `PORT` (default `3000`)
- `VIDEOS_DIR` (Docker default `/data/videos`)
- `BASE_URL` (otherwise request host is used)
- `YOUTUBE_COOKIES_B64` or `YOUTUBE_COOKIES`
- `DB_PATH`
- `STATS_TOKEN`

## Validation

Run `npm test` for the full suite, or `npx vitest run tests/unit.test.js tests/mocked.test.js` for the focused metadata/proxy tests. The MH Stats tests are `tests/mhstats-*.test.js` and run under `npm test`. The browser smoke test needs a running server: `PORT=3999 node index.js &` then `node tools/mhstats/smoke.mjs`; it drives a full two-browser live duel, so it exercises the room routes as well as the page.

## MH Stats deck

Rebuild with `node tools/mhstats/build.js` (see `tools/mhstats/README.md`). Deck numbers come only from the sources, `tools/mhstats/data/refinement.json` or `tools/mhstats/data/curation.json`; never hand-edit `deck.json`. `tools/mhstats/data/curation-report.md` is the audit surface for every value that did not come straight from a game. `public/mhstats/credits.txt` carries required attribution and must ship.

## Self-hosted Docker

Build with `docker build -t ytfx .` and run with a persistent host volume mounted at `/data`. Rebuild and restart only this service when deploying image changes; configure the public `BASE_URL` and required cookies through the runtime environment.
