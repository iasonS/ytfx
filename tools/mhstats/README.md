# MH Stats deck pipeline

Builds `public/mhstats/deck.json` and `public/mhstats/img/` from published Monster
Hunter game data. Outputs are committed, so the Docker build never touches the network.

## Rebuild

```bash
node tools/mhstats/build.js              # rebuild the deck from the committed observations
node --max-old-space-size=4096 tools/mhstats/build.js --refresh   # re-fetch every source first
node tools/mhstats/build.js --groups     # print the tie groups, for the refinement pass
node tools/mhstats/roster.js             # regenerate data/roster.json alone
node tools/mhstats/images.js             # fetch and resize the renders
```

`--refresh` needs the heap flag because the Rise dump is a 118 MB JSON file.

## Stages

| Stage | File | What it does |
|---|---|---|
| Roster | `roster.js` | Wiki category to the 252 mainline large monsters, with each one's newest game |
| Extract | `sources/*.js` | One per source; emits raw observations, never derived stats |
| Merge | `merge.js` | Newest game per input, then fills variant gaps from the base species |
| Scale | `scale.js` | Per-game normalisation to 1..300; HP and Size on a log scale |
| Refine | `refine.js` | Ranks monsters the sources tied, inside the band the data set |
| Curate | `curate.js` | Fills what no source and no base species supplies |
| Build | `build.js` | Runs the chain and writes the deck |

## Rules

- **Never hand-edit `deck.json`.** It is generated. Change a source, the refinement file
  or the curation file instead.
- Every number in the deck traces to `data/observations.csv`, `data/refinement.json` or
  `data/curation.json`. The build fails if a monster ends up with a stat from none of them.
- `data/curation-report.md` is the audit surface: it lists every value that did not come
  straight from a game, with the reason. Read it when reviewing the deck.
- Refinement may reorder monsters the sources **tied**, and may never reorder monsters the
  sources **separated**. `refine.js` enforces that in code and throws on a violation.
- Downloads are cached in `.cache/`, which is gitignored. Extractors must work offline on
  a second run.

## Known source gaps

These are properties of the published data, not bugs. Inheritance and curation fill them.

| Source | Monsters | Missing |
|---|---|---|
| Wilds | 34 | move power |
| Rise | 73 | nothing |
| World | 49 | nothing |
| 4U | 23 | enrage trigger, move power |
| GU | 45 | all four enrage inputs |
| 3U | 20 | base HP, enrage trigger, move power |
| FU | 8 | enrage speed, trigger and duration, move power |

## Credits

`public/mhstats/credits.txt` is generated by `images.js` and must ship with the page.
The wikis' licences require attribution, and one data source's licence names specific
contributors. Do not remove it.

## Quiz bank

`mhstats-quiz-bank.js` at the **repo root** holds the questions for the quiz lobbies
(ADR-017). It is a plain ES module, not JSON, so nothing depends on import attributes being
available in the production image — and it is deliberately not under `public/`, because a
browser that could fetch it would hold every answer in the game.

```bash
node tools/mhstats/derive-quiz-questions.mjs    # regenerate data/quiz-derived.json
node tools/mhstats/build-quiz-bank.mjs \
  tools/mhstats/data/quiz-derived.json \
  tools/mhstats/data/quiz-authored.json         # validate, merge, write the bank
```

| Input | Where the answers come from |
|---|---|
| `data/quiz-derived.json` | Generated from `roster.json` and `deck.json`. Every answer is copied out of a file, and `src` names the field, so it can be re-checked by reading it. |
| `data/quiz-authored.json` | Researched. Every question carries the URL it was checked against. |

### Rules

- **Never hand-edit `mhstats-quiz-bank.js`.** It is generated, and editing it skips every
  check below. Change an input file and rebuild.
- **Every question carries a `src`.** A question that cannot be sourced is not written. The
  builder rejects one without it.
- **Monster Hunter questions stay inside generations 5 and 6** — World, Iceborne, Rise,
  Sunbreak and Wilds. A monster that debuted earlier qualifies if it appears in one of those
  games, which is why the check runs against `roster.json`'s per-monster game list rather
  than against debut. It is enforced on the question **text**, not on the declared `refs`: a
  question can forget to declare a ref, but it cannot forget to name the monster it asks
  about, and a wrong multiple-choice option is still a monster put in front of a player.
  Questions about places and systems name no monster, which is fine.
- **English only.** The builder rejects kana and kanji. Asking which monster is called
  リオレウス tests whether you can read Japanese, not whether you know Monster Hunter.
- A `choice` has exactly four distinct options; an `estimate` has a finite answer and a unit
  a person would actually type — metres, not centimetres.
- Duplicates are caught on question text **plus options**, because "which of these does NOT
  appear in Wilds?" is a different question each time the four monsters change.

`tests/mhstats-quiz-bank.test.js` asserts all of this again, independently of the builder —
a test that called the builder's own validator would only prove it agrees with itself.
